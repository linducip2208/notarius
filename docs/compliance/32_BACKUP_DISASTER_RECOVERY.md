# Backup & DR
Backup DB via mysqldump --single-transaction + defaults-file 0600 (tanpa password di argv/ps), di-pipe gzip | gpg --encrypt ke GPG_RECIPIENT menjadi storage/backups/backup-*.sql.gz.gpg (tombol POST /office/backup → backupNow, audit backup.now); tanpa gpg/GPG_RECIPIENT backup ditolak agar tidak ada plaintext baru. File storage lokal/S3. Skrip deploy/backup/backup.sh + restore.sh memakai MYSQL_PWD (env, bukan -p di argv/ps; portabel Linux + Git Bash). Restore diuji sebelumnya: 0 diff, RTO<60s (docs/qa/RESTORE_TEST.md). Gap: backup file CMS/S3 perlu diuji terpisah; enkripsi backup di VPS (blocker).
File backup plaintext lama (storage/backups/backup-*.sql, sebelum enkripsi) TIDAK dihapus otomatis — hapus manual via tombol "Hapus file plaintext lama" di halaman /office (POST /office/backup/purge-plaintext, konfirmasi ganda, audit backup.purge-plaintext) setelah memastikan backup .sql.gz.gpg bisa di-restore (decrypt: gpg --decrypt file.sql.gz.gpg | gunzip | mysql …).
